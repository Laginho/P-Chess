## Top 3

### 1. P2 / Broken — History rebuilds the entire collection on every progress event

**Location:** `ui/history_screen.gd:656`, calling `_refresh()` at `:149`.

When Stockfish finishes a position, `AnalysisQueue._progress()` emits `changed`. With History visible, its listener deletes every card, reparses every saved PGN through `history.games()`, reconstructs every thumbnail, and creates every card again. Even games unrelated to the active analysis take this path. The temporary 50-game probe blocked the main thread for 3,857 ms for one progress event; a batch repeats this work per analysed position and prevents responsive navigation and controls.

**Proposed change:** retain the cards and parsed records while the collection and tab are unchanged. On progress, update the toolbar and active game's percentage/bar in place. Rebuild on entry, tab changes, deletion, and actual collection changes; update affected state/actions on completion. Keep keyboard focus and the inline delete confirmation attached to the existing card. This needs no new dependency or general UI framework.

**Acceptance:** emit progress with a populated History and assert that unrelated card nodes survive; verify active progress, completion transitions, selection, focus, and deletion confirmation still work. Re-measure the same external workload.

### 2. P2 / Fragile — A failed stats write commits a PGN but reports the game as unsaved

**Location:** `core/history.gd:92`.

`save()` writes the PGN first, mutates the result counters, then writes `stats.cfg`. On failure it returns an empty path while leaving the PGN and mutated W/D/L in place; only the practice counter is restored. The probe produced one saved PGN and one in-memory loss, but after removing the blocked stats destination and constructing a new History, that same PGN coexisted with zero persisted losses. Main also uses an `unsaved-...` analysis filename when the returned path is empty, so its Review cache can become detached from the PGN that actually exists. The existing visible error message does not restore consistency.

**Proposed change:** make the ordinary failed-write path transactional: retain previous counters, stage the PGN/snapshot and stats, and publish success only after the required writes succeed. On failure, restore all counters and remove or roll back newly staged files, reporting any rollback failure. Reuse the existing temporary-file/error-checking patterns. Crash-safe multi-file recovery is a separate decision; do not claim it from ordinary rollback alone.

**Acceptance:** extend the existing failed-stats-write test to reload storage and assert consistent PGN count, W/D/L, practice counts, returned path and analysis association; include a successful save after recovery.

### 3. P2 / Broken — Review accepts an invalid cache that History already treats as stale

**Location:** `ui/review.gd:951`; shared reader `engine/analyser.gd:69`.

`read_analysis()` checks metadata only. Review additionally checks only the positions array's length before merging entries into live state. A metadata-matching two-position JSON cache with empty `pv` arrays and missing terminal scores passes that guard. The real Review probe logged an out-of-bounds access in `core/classification.gd:23`, missing `terminal_score` in `core/accuracy.gd:22`, and a missing `white` value in Review. History and Profile already validate more of the same data, so a game can be labeled stale in History yet still fail when opened for review.

**Proposed change:** put complete-cache validation next to the analysis reader and reuse it in History, Profile and all Review cache-entry paths. Validate position records, scores, PV structure and expected position count before merging anything. Treat invalid data as stale and offer analysis again. Keep incremental, not-yet-scored position data supported separately from complete caches.

**Acceptance:** open a real saved game with metadata-matching caches containing missing scores, empty nonterminal PVs, non-dictionary positions and invalid FENs; each should show the stale/unanalysed state without script errors. Valid cached analysis should still load without starting Stockfish.

## All findings

- **P2 / Broken — `ui/history_screen.gd:656`:** queue progress rebuilds all History cards and synchronously blocks interaction; retain the collection and update the affected card as detailed above.
- **P2 / Fragile — `core/history.gd:92`:** a failed stats save leaves a PGN with counters that disagree after reload; stage writes and roll back the complete failed operation as detailed above.
- **P2 / Broken — `ui/review.gd:951`:** metadata and array length do not establish a usable analysis cache; validate before merging, using the shared boundary described above.
- **P2 / Broken — `core/settings.gd:82`:** when the settings destination is unwritable or its parent is unavailable, `set_value()` ignores `ConfigFile.save()`'s result, emits `changed` and returns true. The probe accepted `Audit Player`, while reloading immediately returned `You`. Profile and the first-name dialog interpret true as success, so they acknowledge a name that will disappear on restart. `save_last_game()` at `:94` has the same unchecked write. Check the save result, retain the prior persisted state on failure, and expose the failure through the affected UI instead of silently accepting it. Add one failed-write/reload regression for both entry points; preserve normal immediate application on successful writes.
- **P2 / Broken — `core/analysis_queue.gd:26`:** persisted queue fields are assigned without schema validation. A parseable queue with `games=[42]` reaches `_start_next()`, sets `_active=true`, then raises an int-to-String assignment error at `:122`; the probe ended with an active queue, empty current path and the invalid entry still pending. Subsequent starts cannot progress while `_active` remains true. Validate the array and its string paths, priority and nonnegative counters before publishing state; discard invalid entries or reset invalid state with a reportable warning. Test restart with malformed values and then enqueue a valid game to verify recovery.
- **P3 / Slop — `ui/review.gd:541`:** `_class_help()` has no caller, and `_wrap_help()` is called only by that unused function. The active help/legend is built separately in `_ready()`. Delete both methods, about 28 lines plus surrounding whitespace; no replacement or dependency is needed. Repository-wide symbol searches found no scene, script or test references.
