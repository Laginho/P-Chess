## What it is

In the Review you can play your own moves from any position of the game and see what Stockfish thinks of them, as on chess.com's game review: "this was a blunder, what if this one instead? ah, Best move".

- **One temporary side line.** A move off the game at ply N starts a line from N. Going back inside the line and playing a different move replaces the rest of the line. **Back to game** returns to ply N. Playing the game's own next move is not a line: it just advances the game. Side lines are never saved: leaving the line or the Review discards it, and Copy PGN, Open in Lichess and the analysis files only ever carry the game.
- **Move list.** The line's moves are extra rows right under the branching move (like the "Left repertoire" rows), with **Back to game** in that block. The game's moves stay listed.
- **Navigation.** Drag or click-click at any ply starts a line. ←/→ and Previous/Next step inside the line, from the branch position to the line's last move. Clicking a game move or the graph, First/Last, Back to game or `Esc` leaves the line. From History, a second `Esc` goes Back to History as today. `F` flips as today.
- **The rest of the screen stays about the game.** Summary, class table and graph do not change; the graph marker stays on the branching move. The eval bar follows the shown position. At 1280×800 the class table collapses behind the "Move classes" button while in a line (as the compact layout always does) and comes back on Back to game.
- **Engine lines** (prototype variant A): a block between the eval graph and the move list, two rows in every layout. Each row: an eval chip in White's view, as the eval bar (light chip when White is better, dark when Black is), then the line in SAN, trimmed with an ellipsis; "depth N" right-aligned on the first row. Game positions show their two stored lines; side-line positions show live lines. The block is hidden on a game position without stored analysis, shows muted "Stockfish is thinking…" rows in a side line until the first result, and shows a single "Checkmate" / "Stalemate" / "Draw" row on a terminal position. In compact, it hides with the graph and the list when "Move classes" opens the table. Clicking a move inside a line plays the line up to that move; clicking the chip plays its first move; the part that matches the game only advances the game.
- **Live engine.** Runs only while you are in a side line, never on plain game positions. The Review starts its own Stockfish (through `analysis_bridge_factory`), Threads = cores − 1, MultiPV 2, an unlimited search on the shown position; it stops when you leave the line or the Review. The background analysis queue is paused meanwhile and resumed after, including the current game's own analysis (progress bar frozen, Stop still works). If Stockfish is missing or stops, the side line keeps working without it and the existing "Analysis: …" message shows; Back to game removes only that message.
- **Live classes.** Each side-line move gets its class icon (on the destination square and beside the move in its row), computed once with the same `Classification.evaluate` as game moves, when its before and after positions have reached the game's criterion: `Tunables.ANALYSIS_NODES` nodes or `Analyser.converged`, whichever comes first. It then stays fixed. No feedback text. The green "should have played" arrow works on side-line moves as on game moves, once the before position is settled.
- **Blue best-move arrow.** A new Settings option, **Best move arrow** (`best_move_arrow`, on by default, after "Legal-move dots"): a translucent blue arrow (`#3f94e0` at about 65%, one constant) for the engine's best move *from the shown position*, under the green arrow and your drawings. Review only. Game positions take it from the stored analysis, side-line positions from the live engine. The existing green arrow is unchanged.
- **The Review's board follows your board settings** (board and piece theme, click-click, auto-queen, legal dots, animation). Today only the game's board gets them.

## Acceptance scenarios

1. **Explore a blunder (Bruno, Windows, real Stockfish).** Open an analysed game from History at a Blunder. Drag a different move for that side: it appears under the blunder's row, the eval bar and the two lines go live with rising depth, and within seconds the move gets its icon (say Best). Click a move inside the second engine line: the line extends to it and each move gets its icon in turn. Back to game: the board is at the blunder again, the line rows are gone, summary and graph never changed.
2. **Rematch from a side line (agent with fakes; Bruno live).** Post-game Review, start a side line, press Rematch: the game starts, the live engine process is gone, and the analysis queue stays paused for the whole game, then resumes as today.
3. **Unanalysed game (agent with fakes; Bruno live).** From History, open a game that is still queued or unanalysed, and explore: the queue pauses (progress bar frozen), the side line gets live lines and classes, Back to game resumes the queue where it was.
4. **Arrow setting (agent).** With Best move arrow on, an analysed game position shows the blue arrow of its stored best move; turning it off in Settings removes it at once, without reopening the Review.
5. **800×600 (agent capture; Bruno look).** In a side line at 800×600, the line rows, Back to game and both engine lines are visible, and the actions stay reachable.

## Test seams

- **The Review scene with a fake engine** (`analysis_bridge_factory` returning a scripted bridge, as `tests/test_review.gd` already does). Catches: wrong side-line state (overwrite, leave, navigation), lines of one position shown on another, the queue left paused or resumed at the wrong time, classes that differ from the game's for the same engine data. Escapes: real Stockfish output quirks and timing, CPU load, how long a class takes to appear. The alternative, real Stockfish in the gate, costs a Windows engine on every run and is impossible on the Linux box. Reversible: a live test that skips without the engine can be added later, like the Lc0 ones.
- **`engine/live_analysis.gd` alone with a fake bridge** (REV-008, REV-009). Catches: search switching (stop, then the new position), the settle criterion, the per-position cache and the order in which unsettled positions are finished. Escapes: the same live-engine risks. Reversible: it is a plain node; folding it back into `ui/review.gd` costs only the move.
- Bruno checks the live engine by hand on Windows before merge (REV-008 and REV-009 are `Review: human`).
